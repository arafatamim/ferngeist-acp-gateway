# Issue tracker: beads

Work items for this repo live in [beads](https://github.com/steveyegge/beads) (`bd`), a Dolt-backed tracker stored locally in `.beads/`. GitHub (the git remote) is **not** the issue tracker; external PRs are not a request surface.

## Conventions

- Issues have short provider-scoped IDs like `ferngeist-acp-gateway-14g.22` (referred to their short form after context, e.g. `14g.22`).
- Every issue carries a **type** (`task`, `bug`, `feature`, `chore`, `epic`) and a **priority** `0`–`4` (`0` = critical, `4` = backlog). The agent-facing triage categories map to types as: `bug` → `bug`, `enhancement` → `task`/`feature`/`chore` as appropriate.
- Epics are parent issues; subtasks link to them with `--parent=<id>`.
- Ordering is expressed with blockers: `--deps=blocked-by:<id>` (or `bd dep add <issue> <depends-on>`). Out-of-scope discoveries are filed with `--deps=discovered-from:<current-id>` instead of being fixed inline.
- `bd dolt push` / `bd dolt pull` sync issues with the remote; treat them like `git push` and only run them when asked.
- Git's `core.hooksPath` is set to `.beads/hooks/`, so git hooks call `bd`.

## When a skill says "fetch the relevant issue"

`bd show <id>`. This prints title, type, description, labels, dependencies, and notes.

## When a skill says "publish to the issue tracker"

`bd create --title="..." --description="why and what" --type=task|bug|feature|epic|chore --priority=2`, optionally with `--parent`/`--deps`.

## When a skill says "tick a checkbox" or "leave a comment"

beads has no comment thread. Record findings by appending text to the issue:

- `bd update <id> --append-notes "..."` for triage notes, review decisions, and agent briefs. Prefix anything auto-generated with the required disclaimer line (e.g. `> *This was generated by AI during triage.*`).
- `bd update <id> --design "..."` for design notes; `--acceptance "..."` sets formal acceptance criteria.

Never run `bd edit` (it opens `$EDITOR` and blocks).

## Wayfinding operations

Not applicable: findings are filed as regular beads issues (with `discovered-from`/`blocked-by` deps as above) rather than scratch trees.
